# AgentIRC Project Architecture and Learnings

## Core Architecture and Technologies
* **Frameworks:** The project heavily relies on **Chainlit** for its UI frontend, presenting a classic 1990s IRC terminal style (via a custom CSS CRT shader), and **AutoGen** (v0.4+) for multi-agent orchestration.
* **Compatibility:** It is tailored for **Python 3.14.3 (experimental)**, requiring specific defensive patches around `asyncio` and `anyio` in `run.py` and `app.py` to prevent breaking background task management.
* **Separation of Concerns:** 
  * `simulator_core.py`: Manages the core domain logic, room configuration, command parsing, transcript formatting, replay utilities, scenario presets, telemetry, and persistence.
  * `app.py`: Acts as the UI gateway, dispatching Chainlit event hooks, handling commands (e.g., `/topic`, `/slap`, `/poll`), autonomous scheduling, and model streaming.
  * `services/agents.py`: Contains the logic for AutoGen agent instantiation (like `AssistantAgent` and `RoundRobinGroupChat`/`SelectorGroupChat`) and team creation.
  * `simulator_tools.py`: Connects AutoGen function-calling to actual implementations (e.g., DuckDuckGo search, `fetch_webpage`). It is strictly required that tools use asynchronous I/O (like `httpx.AsyncClient` or `anyio.to_thread`) to avoid blocking the Chainlit event loop.
  * `bridge_connectors.py` & Bridge Runtimes: Manage external payloads and MCP compliance (routing payloads to Discord webhooks, local inbox/outbox handling, etc.).
* **State Management:** While previously relying heavily on flat `.json` files in `data/`, the system incorporates a SQLite database (`data/simulator.db`) using JSON BLOBs keyed by the authenticated username to handle multi-user concurrency and session persistence.
* **Authentication:** Handled natively by Chainlit's `cl.password_auth_callback` mechanism validating against environment variables.

## Feature Set & Design Patterns
* **Agent Capabilities:** Agents dynamically speak as themselves with persona overrides configured via `agents_config.json`.
* **Dynamic Modding:** Commands like `/add-model` allow parsing runtime arguments (via `shlex`) to dynamically append AI models to the configuration.
* **Room Mechanics & MUD Pivot:** The simulator features multiple segregated rooms. A notable pivot allows the chat to act like a text-based Multi-User Dungeon (MUD) via a `/go` command, forcing agents into a `mud_exploration` roleplay scenario.
* **Operator Polling:** A feature allowing users to prompt all active models to vote on topics via markdown UI streaming (`/poll`).
* **PR Review Scenario:** A specialized scenario using `fetch_github_pr` to fetch diff patches and facilitate evaluation by specific developer-persona agents.
* **Safety Guards:**
  * To prevent context bloat, default agent counts are capped at 10, and brevity notes are dynamically injected into system prompts for heavily populated rooms.
  * Sandbox environment controls ensure that agents cannot write/read to actual project code indiscriminately, forced to operate inside an isolated `.sandbox/` directory.

## Workflows and Documentation Governance
* **Continuous Execution:** A strict design principle ensures an iterative, continuous loop—performing state analysis, merging branches, extracting structural plans, developing features, syncing documents, and committing continuously.
* **Versioning:** Version control is strict; the string resides in `VERSION` and `VERSION.md`. Every version bump requires a `CHANGELOG.md` update.
* **Core Documentation Requirements:** `ROADMAP.md`, `TODO.md`, `VISION.md`, `MEMORY.md`, `DEPLOY.md`, `HANDOFF.md`, and `IDEAS.md` must be dynamically updated with every major feature.
* **Model Overrides:** Files like `CLAUDE.md`, `GEMINI.md`, etc., serve as pointers referencing a universal `AGENTS.md` master configuration. 
* **Testing:** Testing requires setting `PYTHONPATH=.` and executing `python -m pytest tests/` or `unittest discover` from the project root to guarantee local modules (like the bridge connectors) resolve correctly.

* **Agent Orchestration (`services/agents.py`):** Utilizes AutoGen (v0.4+) to instantiate `AssistantAgent`s and coordinate them via `RoundRobinGroupChat` or `SelectorGroupChat`.
* **Tool Catalog (`simulator_tools.py`):** Centralizes functions available to the agents (e.g., `fetch_webpage`, `web_search`). Crucially, all utilities here must utilize asynchronous I/O (e.g., `httpx.AsyncClient` or `anyio.to_thread`) to prevent blocking Chainlit's main async event loop.
* **External Bridging (`bridge_connectors.py` & Runtimes):** Supports routing payloads in/out of the simulator (outbox/inbox/processed) to external services, including fully formatting payloads for Discord webhooks (respecting the 2000 character limit).

## 2. State Management & Persistence
* **Database & Concurrency:** State persistence is handled via a unified SQLite database (`data/simulator.db`), storing state JSON BLOBs keyed by the authenticated username to safely support multi-user concurrency and session segregation.
* **Configuration:** Core simulator states (enabled agents, custom aliases, room topics, lineups, and active features) are loaded and saved dynamically, divorcing runtime configuration from hardcoded parameters.

## 3. Key Features & Design Patterns
* **Dynamic Modding & Admin UI:** 
  * Models can be added at runtime via the `/add-model` command (parsing arguments via `shlex` and updating `AGENT_SPECS`).
  * A dedicated **Admin UI** integrates directly into Chainlit's `ChatSettings` modal (`@cl.on_settings_update` in `app.py`), allowing real-time toggling of active agents and catalog functions without restarting the server.
* **Scenarios & Roleplay Constraints:**
  * **MUD Mechanics:** The `/go <room>` command transitions the simulator into `mud_exploration` mode, forcing agents to roleplay as environmental NPCs in a text-based adventure.
  * **Operator Polling:** The `/poll` command streams a markdown voting UI into the context, forcing agents to vote on user-defined topics.
  * **PR Review:** A specific scenario utilizing the `fetch_github_pr` async capability to evaluate GitHub diffs using personas like 'Security_Auditor'.
  * **Strict Persona Directives:** System prompts rigidly enforce that agents act as themselves and *never* hallucinate fake IRC users or simulate multi-party conversations on their own.

## 4. Technical Constraints & Decisions
* **Python 3.14.3 (Experimental):** The project targets this specific Python build, which requires extreme care. Explicit `asyncio` and `anyio` patches exist in `run.py` and `app.py` to prevent breaking Chainlit and AutoGen's background task loops.
* **Context Window Protection:** To prevent token bloat and performance degradation, default enabled agents are capped at 10. The system dynamically injects brevity notes into prompts when rooms are highly populated. File system access is strictly restricted to an isolated `.sandbox/` directory.

  * **Operator Polling:** The `/poll` command streams a markdown voting UI into the context, forcing agents to vote on user-defined topics.
  * **PR Review:** A specific scenario utilizing the `fetch_github_pr` async tool to evaluate GitHub diffs using personas like 'Security_Auditor'.
  * **Strict Persona Directives:** System prompts rigidly enforce that agents act as themselves and *never* hallucinate fake IRC users or simulate multi-party conversations on their own.
* **Vision & Multi-modal Support:** The application inherently handles multi-modal capabilities. Uploaded image files through the Chainlit UI are intercepted in the `@cl.on_message` handler and translated accurately into `autogen_core.Image.from_file()` objects using PIL, enabling vision-capable models to view files directly within the task array.

## 4. Technical Constraints & Decisions
* **Python 3.14.3 (Experimental):** The project targets this specific Python build, which requires extreme care. Explicit `asyncio` and `anyio` patches exist in `run.py` and `app.py` to prevent breaking Chainlit and AutoGen's background task loops.
* **Context Window Protection:** To prevent token bloat and performance degradation, default enabled agents are capped at 10. The system dynamically injects brevity notes into prompts when rooms are highly populated. File system access is strictly restricted to an isolated `.sandbox/` directory.

## 5. Workflow & Governance Directives
* **Continuous Execution:** Implementors operate on an autopilot directive: pull/sync upstream, merge local branches, execute features, sync docs, and commit autonomously without pausing for confirmation.
* **Documentation Dominance:** A rigorous documentation standard is enforced. Any major change requires immediate, synchronized updates across `VISION.md`, `ROADMAP.md`, `CHANGELOG.md`, `TODO.md`, `MEMORY.md`, `DEPLOY.md`, and `HANDOFF.md`.
* **Versioning:** The project relies on a single source of truth for versions tracked in `VERSION` and `VERSION.md`. Every release bump must reflect across all docs and be referenced in git commit messages.
* **Pre-commit Integrity:** All new features must pass rigorous verification, including localized testing (`PYTHONPATH=. python -m pytest tests/`), frontend verification (if applicable), simulated code reviews, and structured memory recordings before finalizing the implementation.
